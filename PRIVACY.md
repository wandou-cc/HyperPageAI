# HyperPage AI Privacy Policy

Effective date: September 9, 2026

## English

Local TXT and Markdown imports (up to 10 MB) use strict UTF-8 decoding and remain local until selected paragraphs are attached to a request. PDF files (up to 20 MB and 500 pages) are parsed locally in the extension's PDF reader with bundled PDF.js resources. The reader displays extracted text and an outline. Large text previews render visible passages as the user scrolls while retaining the complete extracted original in memory. PDF passwords and original file bytes remain in that tab's memory. Sending a document question includes the complete selected extracted text and page metadata. Original files and passwords are not sent to the provider or stored in conversation archives.

Opening Sources scans the current page's resource links and document, image and video elements locally, recording names, types and URLs in session memory. Scanning does not download files or contact an AI provider. Selecting a supported resource fetches that file under the webpage's access and CORS rules, using credentials only for same-origin requests. PDF and text parsing happens locally. Selected webpage or local images are decoded to PNG locally, with a 5 MB and 16-million-pixel limit; image bytes and the question are sent to the assigned vision provider only on submission. Image attachments remain in completed conversation history, and are included in local storage and JSON archives only when the user saves or exports the conversation. Image conversations do not use web search.

Video reading uses already-loaded native subtitle cues. On YouTube watch pages, explicit subtitle extraction reads the initialized player's current audio track and downloads its first available subtitle track directly from YouTube in the page session. The subtitle file is parsed locally and retains timestamps; the transcript panel and CC need not be enabled. Signed subtitle URLs and their session parameters are not saved or sent to AI providers. HyperPage does not download video or audio, contact a separate subtitle service or generate missing subtitles. Selected subtitle text and source metadata are sent only when the user submits a conversation message. Time references seek within the current video while that video and its source snapshot remain available.

Service credentials are entered only in the extension-owned settings page. Credential input fields are never rendered inside webpages. The floating panel uses a closed shadow root, and saved configuration changes are synchronized through Chrome extension storage.

Workflow archives contain task templates and allowed website origins. Importing them stores new local workflows without executing tasks. Template parameter values are sent as part of the task when it runs and can appear in its execution record. Website scope is checked before extension reads and actions; it does not filter requests issued by the website itself.

Custom prompt templates, categories, favorites and shortcut order are stored locally when changed. Built-in templates do not create stored records until the library is edited. Template use fills a draft; prompt parameter values are sent only when the user submits the message. Saved templates are included in local-data preview, export and deletion.

HyperPage AI does not operate an application server and does not require an account. The developer does not receive or collect personal information, analytics, advertising identifiers, or browsing history. The extension does not passively monitor browsing activity. It processes or transmits data only when the user invokes a feature, as described below.

The extension enable state, named service/model configurations (Base URLs, API keys, model names, output languages and capability check results with timestamps and errors), task-to-model assignments, interface language, result display mode, multi-tab preference, saved workflows, the 20 most recent page-task records and explicitly saved conversations are stored in the user's Chrome profile through `chrome.storage.local`. Element references inserted while composing a page task become editable parts of that task description. Each execution record contains the task description, start and finish times, final status and result, and visible action descriptions and outputs. Action descriptions can include text entered into a page, an option selected by the task, a question asked during execution, or the URL of a tab opened by the task. HyperPage does not add a user's reply as the question action's stored output; the provider-generated final result may reflect information from that reply. These values are not synchronized by HyperPage AI. Local extension storage is not encrypted. Panel visibility is not persisted.

When the user explicitly runs an AI action with an element selected, HyperPage AI sends that element's readable text and limited element metadata directly to the configured Base URL. Actions that require visual input also send a screenshot cropped to the selected element's currently visible area. Conversations attach no new webpage content by default. Users can attach the current page, selected webpage excerpts, a local text file or a video transcript. Conversation attachments do not send screenshots. Page and excerpt reading extract the title, URL, headings and loaded visible text locally, excluding hidden content, scripts, form values, editable areas and embedded frames. Only the selected snapshot content and source metadata are sent. Conversation text is sent without a fixed extension character limit, truncation or automatic splitting into multiple requests. The configured provider determines whether input fits its context capacity, and provider errors are displayed. Each turn automatically includes completed prior turns and their attached original content. Reading snapshots and original-node references for citation navigation remain in page-session memory and are cleared when the conversation is cleared or the page is reloaded.

When web search is enabled in a conversation, the prompt, completed conversation history and selected attachments are sent to the configured provider with its native search tool: Responses web search for OpenAI protocol configurations, Claude web search for Anthropic configurations, or Google Search for Gemini configurations. The provider may send search queries derived from this context to its search providers. Answers include source links returned by the provider. Responses requests use `store: false`; provider processing and retention remain subject to that provider's policies.

Writing requests include the selected readable text, writing mode, tone, approximate length and any additional requirements. Replacing or inserting text into an editable field requires the user's confirmation of the preview. Original contents and undo state remain only in page memory; undo refuses to overwrite subsequent edits. Confirmed edits become visible to the website and are subject to that website's own handling.

The image-analysis tool captures only after the user requests a preview. Capture rejects overlap with marked sensitive fields and embedded content and discards the screenshot if the source tab becomes inactive during capture. The user can crop the preview locally, inspect its dimensions and byte size, copy it or clear it. Image questions, OCR, chart analysis and interface analysis send only the final preview image and the chosen instruction to the configured vision provider after the user starts analysis. The full screenshot and earlier crop versions are not sent by this tool. Image previews remain in page memory and are not saved in conversation archives.

When the user explicitly starts a page task, including a saved workflow, HyperPage AI sends the task description and repeatedly sends a simplified text representation of the current task-controlled page to the configured Base URL. That representation includes the current URL and title, visible page text, interactive-element metadata, and form state that the page exposes to the DOM. Questions generated during execution and the user's answers are also sent to the configured provider as part of that task. The provider returns structured actions that HyperPage AI uses to click, enter text, select options, scroll, modify or remove page elements, or, when the multi-tab preference is enabled, open and control task-owned tabs. Page tasks do not send screenshots and cannot execute model-generated JavaScript.

Page tasks execute requested actions directly without separate approval prompts. They may pause to request missing information and can be stopped by the user. Password fields and fields marked with standard password, one-time-code or payment autocomplete attributes are excluded from readable values and cannot be filled or modified by the task. This protection does not identify sensitive content that a website has not marked with these semantics.

Fetching models sends authenticated requests without page content and follows model-list pagination when required by the selected protocol. Protocol and capability selections are saved locally; changing them does not send a model-generation request. Supported protocols are OpenAI Chat Completions, OpenAI Responses, Anthropic Messages and Google Gemini. Each task uses its assigned service/model; the API key is sent only to that configuration's API origin, and authenticated requests reject redirects. Native tool-call blocks and reasoning signatures are retained only in the active page task's memory for subsequent requests to that same service.

Conversations remain in page-session memory unless the user explicitly saves them. A saved conversation stores its name, prompts, replies, attached element, page, file or transcript snapshots, context and search-mode metadata, timestamps and webpage metadata in local extension storage. Saved conversations can be opened, renamed, searched, exported or deleted in the conversation library. Importing a conversation archive creates new local records. Conversation exports do not include provider settings or API keys. Clearing the current conversation, reloading or navigating the page clears the live session but does not delete saved conversations. Original DOM node references are never saved, so citations in reopened conversations may no longer be locatable on the live page. Page-task DOM representations, screenshots and quick-action results are not independently persisted. An element label inserted into a page task is persisted as part of a saved workflow or execution record. Execution records can be deleted individually or cleared from the history view. The configured AI provider processes and retains requests under its own privacy policy and terms.

The `activeTab` and `scripting` permissions let HyperPage temporarily access and inject its interface into the current HTTP or HTTPS page only after the user clicks the toolbar icon. It cannot run on Chrome internal pages. Access to the configured AI provider is requested separately for that exact host. Broad HTTP and HTTPS access is optional and requested only when the user enables multi-tab tasks, so HyperPage can operate tabs created by that task. HyperPage does not enumerate unrelated existing tabs: it controls only the tab where the task started and tabs created by that task, and it never closes the starting tab. Selecting current-page reading or refreshing its content reads a local snapshot without a provider request. Page content is sent only when the user runs an AI action, sends a conversation turn or starts a page task. The `storage` permission keeps settings, workflows, and execution history locally. The `clipboardWrite` permission writes selected text, PNG images or AI results only after the user chooses a copy action and does not read the clipboard. The `contextMenus` permission provides the enable switch on the extension icon. Disabling HyperPage from that menu removes its page interface and controller. Removing the extension deletes its local configuration through Chrome.

The local-data view displays storage usage and supports preview, JSON export and confirmed deletion of settings, workflows, execution records and saved conversations. API keys are excluded from these previews and exports. Deleting settings removes saved API keys; live conversation memory and Chrome's website grants are separate from saved extension data. The website-permissions view reports effective provider access and granted host patterns, and can revoke those patterns. A broad host grant can continue to cover a provider after its individual grant is removed. Removing website permission stops active AI requests and page tasks.

Questions about this policy can be submitted at [github.com/wandou-cc/HyperPageAI/issues](https://github.com/wandou-cc/HyperPageAI/issues).

## 简体中文

本地 TXT 和 Markdown 文件最多 10 MB，使用严格 UTF-8 解码；选择段落并附加到请求前，内容只在本地处理。PDF 最多 20 MB、500 页，使用随扩展打包的 PDF.js 资源，在扩展阅读器中本地解析并展示提取的正文及目录。大量原文随滚动按可见范围显示，完整提取结果保留在内存中。PDF 密码及原始文件仅保留在该标签页内存中。发送文档问题时携带完整所选段落及页码信息。原始文件和密码不会发送至服务商或写入对话存档。

打开资料模块时，会在本地扫描当前页面的资源链接及文档、图片和视频元素，名称、类型和网址仅保留在当前会话内存中。扫描不会下载文件或请求 AI 服务。选中支持的资源后，才会按照网页的访问及 CORS 规则读取文件，凭据仅用于同源请求。PDF 和文本在本地解析；网页图片及本地图片在本地解码为 PNG，限制为 5 MB 和 1600 万像素。只有发送问题后，才会将图片和提问发送至视觉任务配置的服务。图片附件会保留在已完成的对话历史中，只有用户主动保存或导出对话后，才会进入本地存储或 JSON 存档。图片对话不使用联网搜索。

视频阅读使用原生播放器中已加载的字幕。在 YouTube 播放页，用户主动提取字幕后，会读取已就绪播放器的当前音轨，在该网页会话中直接向 YouTube 下载其提供的第一条字幕轨道。字幕文件在本地解析并保留时间戳，无需打开文字稿面板或开启 CC。带签名的字幕地址及其中的会话参数不会保存或发送至 AI 服务。HyperPage 不下载视频或音频，不请求额外字幕服务，也不生成缺失字幕。只有用户发送对话消息后，才会发送所选字幕及来源信息。引用定位在当前视频及其来源快照仍可用时跳转到对应时间。

服务凭据仅在扩展自己的设置页中输入，网页内不渲染凭据输入框。浮动面板使用封闭的 Shadow DOM，已保存的配置变更通过 Chrome 扩展存储同步。

流程文件包含任务模板和允许的网站源站；导入仅保存为新的本地流程，不会执行任务。运行时填写的模板参数作为任务内容发送，并可能保留在该任务的执行记录中。插件在读取和操作前检查网站范围，该范围不用于过滤网站自身发出的请求。

自定义提示模板、分类、收藏状态和快捷动作顺序在修改后保存在本地。内置模板在用户编辑模板库前不产生存储记录。使用模板只填入对话草稿，填写的模板参数在用户发送消息后才会传给 AI 服务。已保存模板支持本地查看、导出和清除。

HyperPage AI 不运营应用服务器，也不要求用户注册账号。开发者不接收或收集个人信息、分析数据、广告标识符或浏览历史，插件也不会在后台持续监控用户的浏览行为。只有当用户主动使用下述功能时，插件才会处理或发送相关数据。

插件启用状态、命名的服务与模型配置（Base URL、API Key、模型名称、输出语言、能力检测结果及时间和错误）、任务使用的模型、界面语言、结果展示方式、多标签页任务设置、用户保存的固定流程、最近 20 条页面任务执行记录，以及用户主动保存的对话，通过 `chrome.storage.local` 保存在当前 Chrome 配置中。编写页面任务时插入的元素引用会成为可编辑任务描述的一部分。每条执行记录包含任务描述、开始和结束时间、最终状态与结果，以及界面可见的动作说明和动作结果；动作说明可能包含任务向网页输入的文字、选择的选项、执行中提出的问题，或任务打开的标签页 URL。HyperPage 不会把用户回复直接写入该提问动作的存储结果；AI 服务生成的最终结果仍可能体现回复中的信息。HyperPage AI 不同步这些数据，扩展本地存储也不等同于加密存储。面板是否打开不会持久化保存。

当用户选中元素并主动执行 AI 操作时，HyperPage AI 会把该元素的可读文字和必要的元素信息直接发送到用户配置的 Base URL。需要视觉输入的操作还会发送所选元素当前可见区域的裁剪截图。对话默认不附加新的网页内容，用户可附加当前页面、所选网页片段、本地文本文件或视频字幕；对话附件不发送截图。页面及网页片段阅读在本地提取标题、URL、标题层级及已加载的可见正文，排除隐藏内容、脚本、表单值、可编辑区域和嵌套框架。仅将所选快照内容及来源信息发送至 AI 服务。对话文字按所选范围完整发送，插件不设固定字符上限、不截断原文、不自动拆分为多次请求。输入是否符合模型上下文容量由配置的服务决定，服务返回的错误会展示给用户。每轮对话自动携带已完成的历史轮次及其附加原文。阅读快照及用于引用定位的原始节点引用仅保留在当前页面内存中，清空对话或刷新页面时清除。

在对话中启用联网搜索后，提问、已完成的对话历史及所选附件连同原生联网搜索工具请求发送至配置的服务：OpenAI 协议配置使用 Responses 联网搜索，Anthropic 配置使用 Claude 联网搜索，Gemini 配置使用 Google Search。服务商可能根据这些上下文生成查询并发送给其搜索服务。回答包含服务返回的来源链接。Responses 请求设置 `store: false`，服务商如何处理和保留数据仍受其自身政策约束。

写作请求包含所选可读文字、写作类型、语气、近似长度和补充要求。替换可编辑内容或在光标处插入文字前，需要用户确认预览。原内容及撤销状态仅保留在页面内存中，撤销不会覆盖后续编辑。确认后的修改对网站可见，并受该网站自身的数据处理方式影响。

图片分析工具仅在用户主动请求预览后截取图片。截图范围与已标记的敏感字段或嵌入内容重叠时会阻止截取；截图期间来源标签页失去活动状态时，会弃用该截图。用户可在本地裁剪预览、查看尺寸及字节数、复制或清除图片。只有用户开始分析后，图片问答、OCR、图表分析和界面分析才会把最终预览图片及所选指令发送至视觉任务配置的服务；该工具不会发送完整屏幕截图或先前的裁剪版本。图片预览仅保留在页面内存中，不写入对话存档。

只有当用户主动启动页面任务（包括点击执行已保存的固定流程）时，HyperPage AI 才会把任务描述和当前任务所控页面的简化文本表示逐步发送到用户配置的 Base URL。该内容包括当前页面 URL 和标题、可见网页文字、可交互元素信息，以及页面通过 DOM 暴露的表单状态。执行中由模型生成的问题和用户回答也会作为该任务的一部分发送给配置的 AI 服务。AI 服务返回结构化操作，HyperPage AI 会据此执行点击、输入、选择、滚动、修改或删除页面元素；启用多标签页任务后，还可以打开并操作任务自己创建的标签页。页面任务不会发送截图，也不允许执行模型生成的 JavaScript。

页面任务按用户描述直接自动执行，不设置额外审批。缺少必要信息时可以暂停提问，用户可停止任务。原生密码字段及通过标准 autocomplete 属性标记的密码、验证码和支付字段，不会作为可读值发送，也不允许任务填写或修改；该保护不能识别网站未使用这些语义标记的敏感内容。

获取模型时会发送不包含网页内容的认证请求，并按所选协议读取模型列表的后续分页。协议和能力选项保存在本地，修改选项不会发起模型生成请求。支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini 协议。每项任务使用用户指定的服务和模型，API Key 只发送至该配置的 API 源站，认证请求不跟随重定向。原生工具调用内容和推理签名仅保留在当前页面任务的内存中，用于向同一服务发送后续请求。

对话默认仅保留在当前页面会话内存中。用户主动保存后，对话名称、提问、回复、附加的元素、正文、文件或字幕快照、上下文及联网搜索模式信息、时间及网页信息会保存在扩展本地存储中。已保存对话可在对话库中打开、重命名、搜索、导出或删除；导入对话存档会创建新的本地记录。对话导出不包含服务设置或 API Key。清空当前对话、刷新或跳转页面会清除当前会话，但不会删除已保存的对话。原始 DOM 节点引用不会保存，因此重新打开的对话引用可能无法在实时页面中定位。页面任务 DOM 表示、截图及快捷操作结果不会单独持久化。元素标签会作为用户保存的流程或执行记录中的任务描述保存。执行记录可逐条删除或全部清空。用户配置的 AI 服务商将依据其自身隐私政策和服务条款处理及保留请求。

`activeTab` 和 `scripting` 权限仅在用户点击工具栏图标后，用于临时访问当前 HTTP 或 HTTPS 网页并注入 HyperPage 界面；Chrome 内部页面不在可运行范围内。插件会针对用户配置的 AI 服务单独申请该服务域名的访问权限。只有用户开启多标签页任务时，插件才会申请可选的 HTTP 和 HTTPS 网站访问权限，用于操作本次任务创建的标签页。HyperPage 不会枚举无关的已有标签页，仅控制任务发起页和本次任务创建的标签页，也不会关闭任务发起页。选择当前页面阅读或刷新正文时，仅提取本地快照，不请求 AI 服务；执行 AI 操作、发送对话或启动页面任务后才会发送相关网页内容。`storage` 权限用于在本地保存设置、固定流程和执行记录；`clipboardWrite` 权限仅在用户主动复制时写入所选文字、PNG 图片或 AI 结果，不会读取剪贴板；`contextMenus` 权限用于在扩展图标上提供启用开关。从该菜单停用 HyperPage 后，网页界面和页面控制器都会移除。卸载扩展后，Chrome 会删除扩展的本地配置。

本地数据界面展示存储用量，支持按类别预览、导出 JSON，以及确认后清除设置、固定流程、执行记录和已保存对话；这些预览和导出不包含 API Key。清除设置会删除已保存的 API Key；当前对话内存及 Chrome 网站授权与扩展已保存数据分别管理。网站权限界面展示 AI 服务的实际访问状态和已授权域名范围，并支持撤销授权。撤销某个服务的单独域名授权后，通配网站授权仍可能覆盖该服务；撤销网站权限会停止正在执行的 AI 请求和页面任务。

如对本隐私政策有疑问，可通过 [github.com/wandou-cc/HyperPageAI/issues](https://github.com/wandou-cc/HyperPageAI/issues) 联系。
